## 2. Shared interface (matches the common interface brief)

- **Default image** is resolved dynamically from the actual origin:
  GitHub → `ghcr.io/<lowercased GITHUB_REPOSITORY>`
  (→ `ghcr.io/azurekiln2333/codearts2api` for this repo). CNB →
  `docker.cnb.cool/$CNB_REPO_SLUG_LOWERCASE`, overridable with
  `CA2A_IMAGE` / `CNB_IMAGE`, and registry auth overridable with
  `CNB_REGISTRY` / `CNB_REGISTRY_USER` / `CNB_REGISTRY_PASSWORD`
  (defaults to the platform-issued `CNB_DOCKER_REGISTRY` + `CNB_TOKEN`).
- **`latest` only for stable tags.** `vX.Y.Z` produces image tags
  `<image>:vX.Y.Z` and `<image>:latest`; `vX.Y.Z-prerelease` produces only
  `<image>:vX.Y.Z-prerelease` and is published as a GitHub pre-release
  (`--prerelease`) / CNB `preRelease:true, latest:false`. No inline
  `docker push/tag … :latest` exists anywhere — the tag list always comes from
  the helper.
- **One tag gate, no illegal tags.** `validate-tag` is the first step of both
  `v*` pipelines and refuses: anything that is not `vX.Y.Z[-prerelease]`, any
  build metadata (`+...`), and any base or `-<arch>` tag that is not a legal
  container tag or exceeds 128 characters. `latest` and every CNB intermediate
  `-amd64` / `-arm64` ref come from the helper (`image-tags`, `arch-tags`), so no
  tag is ever built inline. Covered by real CLI regressions, not only a parse
  check.
- **One GitHub gate, no duplicated CI cost.** `.github/workflows/go.yml` was
  deleted. `build-and-release.yml` already runs every Go check (test / race /
  vet / build) and all Python suites, and already triggers on `push` (`main` +
  `v*`), `pull_request` and `workflow_dispatch`, so it is the only GitHub gate;
  there is no second workflow paying for the same tests. The manifest retires
  `go.yml` accordingly.
- **Credentials are checked before any build.** `guard-registry` fails the
  pipeline up front when the image registry is not the platform registry
  (`CNB_DOCKER_REGISTRY`) and `CNB_REGISTRY_PASSWORD` is unset, so a
  misconfigured custom registry cannot silently fail at the final push with
  `unauthorized`. When credentials are present, the login targets the *image's*
  registry (`IMAGE_REGISTRY`) rather than a possibly different default.
- **Go 1.27 toolchain alignment.** GitHub `setup-go` uses `1.27.x` and the CNB
  runtime is `golang:1.27-alpine`, matching p4's `Dockerfile`
  (`GO_VERSION=1.27` / `ALPINE_VERSION=3.24`) so CI, CNB and the image build all
  use the same compiler. `go.mod` still declares `go 1.22`.
- **Build identity** is the full commit plus a UTC build time: GitHub uses
  `${{ github.sha }}` + `date -u`; CNB uses `$CNB_COMMIT` + `date -u`. Both are
  passed as the Dockerfile `BUILD_COMMIT` / `BUILD_TIME` build args.
- **Explicit source manifest** is generated by the existing
  `scripts/release-source.py`; the helper only chooses the *output path*
  (`archive-path` uses an explicit temp path, and falls back to a fresh temp
  dir when the commit-named ZIP already exists, so a same-commit re-run never
  overwrites the artifact). Archive name stays
  `codearts2api-source-<commit12>.zip` on **both** GitHub (`$RUNNER_TEMP/<name>`)
  and CNB (`dist/<name>`) so every release asset carries the commit identity;
  only the release tag, checksums, notes and manifest are versioned.
- **CNB race toolchain.** `go test -race` needs cgo, so every `prepare-tools`
  stage installs `build-base` (gcc + musl-dev) and the race job runs
  `CGO_ENABLED=1 go test -race ./...`. The image stages build inside Docker and
  stay independent of the host toolchain.
- **Arch intermediate tags are documented, not deleted.** Each arch is pushed as
  `<image>:<tag>-amd64` / `<image>:<tag>-arm64` and then folded into the
  multi-arch manifest with `docker buildx imagetools create`. These per-arch
  tags stay in the registry (deleting them would need extra delete
  permissions) and are harmless; only the version tag and `latest` are the
  published contract.
- **Idempotent re-runs.** CNB `git:release` uses `overlying:true` (update, never
  delete-then-recreate). GitHub re-runs use
  `gh release view → upload --clobber + edit`, else `gh release create`.

## 3. Trust model

- GitHub: top-level `permissions: contents: read`. Only the `test` job runs for
  PRs; `release` (`contents: write`) and `image` (`packages: write`) are gated by
  `if: … startsWith(github.ref, 'refs/tags/v')` and `needs: [test]`.
- CNB: `main`/`pull_request` never authenticate or publish (no `docker login`,
  `docker push`, `--password-stdin`, `git:release`, `gh release`, `CNB_TOKEN`).
  The `v*` image job re-runs the full tag validation and Go/Python suite in its
  own pipeline, so an image can never bypass the release gate.
