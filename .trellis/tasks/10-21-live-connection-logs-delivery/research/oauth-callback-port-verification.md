# OAuth callback-port verification

Date: 2026-10-24. Scope: R16 callback-port correctness and configuration comments.

## Confirmed defect

`adminOAuthStart` previously built the authorization URL using the listen port,
then rewrote only that URL's port when `OAuthCallbackHost` had an explicit port.
The OAuth session and legacy pending login still retained the old listen port.
Consequently, a genuine callback generated by that URL could fail import port
validation, and authorization-code exchange could use a different redirect URI.

The repaired implementation determines the effective callback port before
building the URL or storing either session. Authorization URL, session, pending
login, callback import validation and code exchange now share that port. The
obsolete URL-only rewrite helper was removed. The start response also names the
unified Submit authorization action instead of the removed I have authorized
control.

`OAuthCallbackHost` remains a compatibility setting that uses an explicit port
only. It cannot replace the upstream's fixed loopback host. Corrected the handler
and runtime-config comments and the helper comment: a remote browser cannot
reach the deployment host by redirecting to its own 127.0.0.1 address. Manual
callback import remains the existing authenticated bridge. No unsupported public
redirect URI, PKCE/DPoP behavior, credential persistence or upstream protocol was
introduced.

## Actual-route regression

`TestOAuthCallbackPortMatchesAuthorizeSessionAndCodeExchange` exercises the
registered authenticated start/import routes and an actual localhost STS token
endpoint for three cases:

- Listen7866 with explicit callback8443: all boundaries use8443.
- Listen21508 with no override: all boundaries use21508.
- Listen7866 with an HTTPS host lacking an explicit port: keep7866; do not infer443.

Each case asserts the authorization query port, OAuth-session and legacy-pending
ports, wrong-port callback rejection with zero token exchanges, accepted
secret/redirect continuation, accepted final code callback, actual STS form
redirect_uri and retained PKCE verifier, completed-session removal and saved
refreshable synthetic credentials. Existing direct-callback/poll, imported-code,
legacy-ticket guard, continuation validation and candidate matching tests remain
passing.
